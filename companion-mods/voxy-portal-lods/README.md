# Voxy portal-LOD ipa10p1

The pack ships a private NeoForge build of Voxy, `voxy-0.2.17-alpha-sodium08-portal-lods-ipa10p1.jar`, from `.pakku/overrides/mods`. There is no Voxy source tree in this repo. The jar is Voxy 0.2.17-alpha retargeted at NeoForge 1.21.1 and Sodium 0.8, plus the Immersive Portals: Aeronautics portal-LOD changes (`ImmPortalsCompat`, `PortalPassState`, portal viewports in `ViewportSelector` and `VoxyRenderSystem`). Those changes are not in a public fork.

ipa10m starts the ring on the view-distance square and skips columns the server has already sent. ipa10n also skips columns the client built itself. ipa10o does not park the ring when a saved chunk produces no LOD. ipa10p sends up to 32 columns in one tick when the server is under 40 ms, keeps the coverage scan running until storage is open, and applies a packet for the player's world while the render level is swapped. ipa10p1 keeps that behaviour and returns the player's `ClientLevel` from `TerrainReceive.acceptLevel`, so `tickDrainApplyQueue` can call `registryAccess`, `getMinSection`, and `getMaxSection`. ipa10p passed a `Level` into those `ClientLevel` calls and the client died with `VerifyError`. After hello, the client sends `voxy:column_coverage`: one 32×32 chunk bitmap (128 bytes) per region, nearest region first, up to four regions a tick. Hello itself is still two varints on channel version 2. An older peer that does not have the new packet keeps streaming. `build.sh` reads the ipa10o jar and writes ipa10p1. It runs `StreamHarness`, `RingHarness`, and `TintSafetyHarness`, then `VerifyJar`, which runs ASM `CheckClassAdapter.verify` on every class against the Mojmap 1.21.1 client and server and the NeoForge libraries.

Kill switch, unchanged: `-Dvoxy.portalLods=false`. Server LOD packets still require `server_terrain_sync_broadcast` in `config/voxy-config.json`. An inner radius of 0 means "use the player's view distance"; a positive value is a fixed override. Set `server_terrain_sync_debug` to true for the periodic walker summary. The summary includes `clientHeld` and `skippedClient`.

A client report is stale once the server loads that chunk again. The reload is remembered for the rest of the server run, so a later report cannot put the column back. Edits that never reload the chunk are not detected.
